> AMAS 亚洲宣教神学院 · Christian Formation System
> 状态：完整版已上线（App 主阵地 + Web Discover 公开入口）
> 更新：2026-08-26

---

## 1. 系统定位

本系统不是一次性的“属灵测试”，而是一个**持续运转的成长闭环**：

```
ASSESS 评估 → PROFILE 画像 → RECOMMEND 推荐 → LEARN 学习
    ↑                                              ↓
REASSESS 复诊 ← VERIFY 验证 ← SERVE 服事 ←──────────┘
```

- **评估**：AI 自适应诊断（九维阶梯题）+ 恩赐辨识（含情境行为题）
- **画像**：九维分数、成长阶段（LEVEL 1–4）、优势/短板、风险提示
- **推荐**：三阶段装备路径（课程 + 实践任务 + 检验标准）、事奉方向匹配
- **学习**：完成课程自动反哺画像分数（学习佐证 ↑）
- **服事**：服事记录填充恩赐证据层；一键提交事奉申请到教务
- **复诊**：随时重新诊断，画像带时间戳，可随时撤销

**神学边界**：所有诊断与建议在 AMAS 神学框架内进行，以圣经为最高权威，
以学院官方教学为准。结果仅作装备参考，不构成对个人信仰状态的评判。

## 2. 九维模型

| 维度 | key | 说明 |
|---|---|---|
| 圣经基础 | `bible` | 圣经整体脉络与书卷框架 |
| 解经能力 | `hermeneutics` | 观察—解释—应用的释经流程 |
| 系统神学 | `theology` | 教义框架与真理表述的准确性 |
| 福音根基 | `gospel` | 因信称义、恩典与成圣 |
| 属灵生命 | `life` | 灵修节奏、属灵纪律 |
| 教会生活 | `church` | 教会观、圣礼、肢体委身 |
| 事奉能力 | `ministry` | 带领、门训、讲道预备 |
| 护教分辨 | `apologetics` | 正统信仰判断与异端识别 |
| 宣教使命 | `mission` | 大使命、处境化、职场家庭见证 |

每个维度定义了：4 档分数段诊断语（<45 / 45–64 / 65–79 / ≥80）、
训练要点、实践任务、检验标准、对应课程与预计周数。

### 四层能力标尺

每个维度按 **知道 → 理解 → 应用 → 教导** 四层递进衡量，
阶梯题的三级（level 1/2/3）分别对应 知道、应用、教导。

## 3. 自适应诊断引擎（结构化，非 LLM 打分）

### 流程

1. **背景题（6 题，有跳题逻辑）**：角色层级 tier(0–3)、信主年限、装备经历、
   优先需要（focus 维度）、现实处境（scenario）。
2. **核心五维阶梯题**（bible/hermeneutics/theology/gospel/ministry，各 2 题）：
   - tier ≥ 2 的用户从 level 2 起步，否则从 level 1；
   - 答分 ≥70 → 升一级追问；<50 → 降一级；第二题权重 1.4；
   - 已到顶层还答 ≥70 → 额外加权记分（+4 分、权重 0.6）；
   - 用户选择的 focus 维度排在最前。
3. **单题四维**（life/church/apologetics/mission 各 1 题）。
4. **汇总**：加权平均得九维分数；选择了处境的维度轻微下调（-5）以突出该处境的装备需要。

### 一页一题答题（UX 约定）

- 全部测评（诊断 + 恩赐）均为**一页一题卡片式**，不做滚动式聊天流。
- 顶部进度条 + `N/总数` 计数，卡片内 `第 N 题` 标签。
- **随时撤销**：每答一题压入历史快照（引擎完整状态序列化），
  「上一题」按钮弹出快照并恢复，可一路撤回到第一题。
- 左上角 ✕ 可随时退出，不保存中途状态。

### 成长阶段

| 阶段 | 条件 |
|---|---|
| LEVEL 4 成熟装备者 | 均分 ≥78 且 tier ≥2 |
| LEVEL 3 成长型服事者 | 均分 ≥63 |
| LEVEL 2 稳定成长者 | 均分 ≥47 或信主 ≥3 年 |
| LEVEL 1 初信扎根者 | 其余 |

### 风险规则（装备顾问提醒）

- 带领/教导岗位（tier≥2）但福音根基 <62 → 提醒优先补救恩论；
- tier≥2 但解经 <58 → 提醒尽快完成释经训练；
- 处境为异端接触且护教 <60 → 提醒优先处境任务并寻求教牧支持;
- tier≤1 但事奉 ≥80 → 提醒服事超前于装备，防止透支。

## 4. 恩赐辨识与事奉匹配

- **8 项恩赐**：教导、牧养关怀、传福音、带领治理、服事帮补、劝勉鼓励、怜悯、分辨。
- **12 题**：10 题恩赐倾向 + 2 题情境行为题（形成「行为佐证」分）。
- **证据四层**（逐层解锁，防止“测评即定论”）：
  1. 自我评估 — 测评即得；
  2. 行为佐证 — 情境题得分；
  3. 实际服事 — 用户记录的服事条目（按恩赐计数）；
  4. 他人评价 — 待导师/同工后台开通（规划中）。
- **事奉方向匹配**：6 个角色（小组带领、门训陪伴、主日学教师、关怀探访、
  福音外展、后勤服事），按恩赐加权求匹配度百分比。
- **事奉申请（Phase 7）**：匹配卡片上一键「申请」→ 经合作/联络通道
  （`submitCooperation`，type=事奉申请）提交到教务，本地标记「已申请」。

## 4.5 成长角色（Christian Growth Archetypes）

角色体系是档案的**解释层**：把恩赐分数、九维能力与服事证据翻译成用户
能记住并行动的「成长角色」。它不是属灵等级、恩赐排他认证或呼召判断。

### 十二角色 × 四大群组

| 群组 | 核心问题 | 角色 |
|---|---|---|
| TRUTH 真理型 | 我如何帮助人更准确地认识并活出真理？ | 教导者、研道者、装备者 |
| CARE 生命型 | 我如何陪伴、扶持与建造人的生命？ | 牧养者、劝勉者、怜悯者、代祷者 |
| MISSION 使命型 | 我如何把福音带到尚未被触及的人群中？ | 传福音者、差传者 |
| BUILD 建造型 | 我如何建立团队、系统与实际摆上？ | 领袖者、建造者、服事者 |

每个角色定义：核心动机、常见优势、潜在盲点、适合探索的侍奉、
推荐装备方向、恩赐权重、九维权重、图标。

### 角色算法（多来源证据，绝不单靠恩赐测评）

```
角色得分 = 恩赐加权 62% + 九维能力加权 38%（含学习反哺后的展示分）
         + 实际服事证据加成（该角色主要恩赐的服事记录，每条 +2，上限 +6）
```

输出为**主角色 × 辅助角色 × 第三倾向**，组合命名 = 辅角色修饰形 +
主角色（如「装备型教导者 The Teacher–Equipper」「劝勉型牧养者」）。

### 角色确认度（6 层证据核对）

自我评估 / 行为佐证 / 神学能力 / 课程表现 / 实际服事 / 导师反馈（规划中）。
按已具备的证据数分级：≥5 高、4 较高、3 中等、≤2 初步。

### 动态角色（Dynamic Archetype）

角色不永久固定：主+辅组合发生变化时自动追加 `roleHistory` 版本记录
（Profile V1 → V2 …），并在卡片上展示演变轨迹——变化被解释为
生命阶段的发展，而非测评失误。

### 强制免责声明（每个角色结果页展示）

> 成长角色用于帮助理解当前呈现的恩赐、能力、侍奉与成长倾向，不等同于
> 属灵身份、教会职分或神对个人呼召的最终确认。角色判断应继续结合圣经、
> 祷告、教会群体、导师、真实侍奉与长期果效进行辨识。

## 5. 学习反哺（Phase 4 闭环）

`COURSE_DIM_MAP` 将全部课程映射到维度（如 罗马书→gospel、圣经概论→bible、
个人布道→mission+ministry）。用户**每完成一门**映射课程，对应维度显示分
**+4，单维上限 +12**，画像条目右侧显示绿色 ↑，画像顶部注明已计入课程数。
诊断原始分保持不变——反哺只作用于展示层，复诊时以新答题为准。

---

## 6. 服事验证（Phase 6 证据层）

- 「＋记录一次实际服事」→ 全屏表单：选择恩赐、服事内容（必填）、反思（选填）。
- 记录填充对应恩赐的「实际服事」证据点，并使档案完成度 +15%。
- 主页「服事记录」区展示最近 5 条。

### 档案完成度

| 模块 | 权重 |
|---|---|
| 背景与处境 | 15% |
| 神学九维画像 | 35% |
| 恩赐辨识 | 20% |
| 学习佐证（≥1 门完成课程） | 15% |
| 服事验证（≥1 条服事记录） | 15% |

渐进式建档：完成诊断即可用，其余模块随时补齐，不强制一次做完。

## 7. 数据与同步

### 档案结构（CTState v2）

```ts
{
  v: 2,
  tier, years, focus, scenario,
  scores: Record<9维, number>,   // 诊断原始分
  levels: Record<维度, 1|2|3>,   // 达到的阶梯层
  completedAt: ISO 时间戳,
  gifts?: { scores: Record<8恩赐, number>, behavior, completedAt },
  service?: [{ gift, role, note, at }],
  applications?: [{ role, at }],
}
```

### 存储

- **localStorage** `amas_ct_state_v2` — 即时启动；
- **后端** `PUT/GET /api/growth/state`（`growth_state` 表，user JWT 归属，
  512KB 上限）— 跨设备共享；
- **合并策略**：completedAt（恩赐优先）较新者胜；写入走 1.5s 防抖推送；
- 未登录/未配置后端时静默降级为纯本地模式。

### 后端

- `backend/src/routes/growth.ts` — 路由；`backend/src/db.ts` — 表结构；
- 测试：`backend/src/test/smoke.test.ts`（未授权 401、round-trip、用户隔离）。

## 9. AI 的角色边界

- **结构化引擎负责一切打分与判定**（题库、权重、规则），保证可解释、可复现；
- LLM（配置 `GEMINI_API_KEY` 后）仅用于：解释诊断结果、追问澄清、
  处境任务的模拟对话训练——不参与打分；
- 未配置 LLM 时系统完整可用（当前默认状态）。
